## 4 · Banco dividido com o GL Suite

**Por quê:** a org "GuessLess - products" está no plano gratuito, e os admins
já têm o máximo de projetos gratuitos ativos. O Arthur escolheu usar um
projeto existente em vez de subir a org para Pro ou pausar outro projeto.

**Onde:** projeto `GL Suite` (o ref fica no painel do Supabase), região us-west-2
(Oregon). O épico pede São Paulo; para teste, ficou assim.

**Como ficou:**
- As 19 tabelas do SDR (`perfis`, `leads`, `acoes`, `mensagens`, etc.) ficam
  no schema `public`, ao lado das 140 do GL Suite. Não há colisão de nome.
- As migrations até `20260929230000` foram aplicadas **por SQL**, fora do
  histórico `supabase_migrations`, que é do GL Suite. Registrar lá quebraria
  o `supabase db push` do repositório do GL Suite.
- O app conecta como **`sdr_servidor`**, um papel próprio, e não com a senha
  principal do banco:
  - `BYPASSRLS` e direitos só nas tabelas do SDR (os jobs do sistema
    ignoram RLS, como antes);
  - membro de `authenticated` com `inherit false, set true`: o painel troca
    para `authenticated` e o RLS vale; sem herança, ele não ganha o acesso
    que esse papel tem às tabelas do GL Suite;
  - verificado: o `sdr_servidor` não lê nenhuma tabela do GL Suite.
- Conexão pelo pooler em modo transação, com o usuário `sdr_servidor.<ref>`
  (host e ref no painel do Supabase, em Connect). O host `aws-0` não
  funciona para este projeto.
- O login usa o Auth do GL Suite, com `shouldCreateUser: false`.
- Admin inicial: midia@. Operador de teste: arthur@, ligado ao perfil
  Arthur (`perfis.operador_id` e `operador_perfis`).

**Regras para quem mexer no banco:**
- Migration nova do SDR: aplicar por SQL (conector do Supabase ou `psql`),
  nunca por `supabase db push`, `supabase migration up` ou
  `apply_migration`, que gravam no histórico do GL Suite.
- Tabela nova: declarar o próprio grant para `authenticated` e para
  `sdr_servidor`. Nunca `grant`/`revoke`/`alter default privileges` em
  `all tables in schema public`.
- Nunca `supabase db reset` nem `supabase config push` no GL Suite.

**Saída:** quando houver cota ou plano Pro, criar um projeto próprio em São
Paulo, aplicar as migrations normalmente, levar os dados (se houver) e trocar
as variáveis na Vercel. Depois, apagar as tabelas do SDR e o papel
`sdr_servidor` do GL Suite.
